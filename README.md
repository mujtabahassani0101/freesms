# FreeSMS — نسخهٔ بومی ویندوز با .NET 10

این نسخه از سورس بازیابی‌شدهٔ `school_af.exe` ساخته شده است: ۲۰۵ واحد C#، ۸۹ فرم اصلی، منطق ثبت‌نام، نمرات، حضور و غیاب، مالی، کاربران و منابع SQL در همین مخزن قرار دارند. کار فقط در پوشهٔ مستقل `free-sms` انجام می‌شود.

برنامه، کنترل‌ها، نمایش و چاپ گزارش و آماده‌سازی بانک همگی در .NET 10 اجرا می‌شوند. کنترل‌های قدیمی Janus، تقویم و ActiveReports با کنترل‌های C# جدید جایگزین شده‌اند. موتور جدید گزارش، قالب‌های XML استخراج‌شده از گزارش‌های اصلی را می‌خواند. ظاهر بعضی کنترل‌ها و گزارش‌ها تغییر کرده است.

برای اجرای برنامه Docker، WSL، Wine، Python، .NET Framework یا Crystal Runtime لازم نیست. کلید سخت‌افزاری لازم نیست؛ ورود، گذرواژه و مجوزهای کاربران اصلی حفظ شده‌اند.

## اجرا روی ویندوز

1. ویندوز x64 و SQL Server Express LocalDB نسخهٔ ۲۰۱۹ یا جدیدتر لازم است. خود برنامه x86 است تا با مسیرهای Excel و منابع اصلی سازگار بماند.
2. بستهٔ خروجی را کامل استخراج و `FreeSMS.exe` را اجرا کنید. پوشه‌های بانک اولیه، قلم‌ها و `portable-layouts` باید کنار برنامه باشند.
3. محیط اجرای .NET 10 همراه خروجی مستقل قرار دارد؛ نصب SDK برای استفاده از بسته لازم نیست.

برای واردکردن و صادرکردن فایل‌های Excel، مسیرهای اصلی Office/Access باقی مانده‌اند؛ بسته به عملیات، نصب مؤلفهٔ سازگار ۳۲ بیتی لازم است. چاپ و پیش‌نمایش گزارش از امکانات بومی ویندوز استفاده می‌کند. ذخیرهٔ تصویر PNG، خروجی Excel با قالب XLSX بدون نیاز به Office، و چاپ به PDF از پنجرهٔ چاپ ویندوز در دسترس است. خروجی XLSX جدید، داده‌های فیلترشدهٔ گزارش را به صورت جدول ذخیره می‌کند؛ مسیرهای Excel قدیمیِ فرم‌ها همچنان وابستگی‌های خود را دارند.

بستهٔ ساخته‌شدهٔ ویندوز در [خروجی آزمون موفق](https://github.com/mujtabahassani0101/freesms/actions/runs/41490887246/artifacts/13163848205) قرار دارد. این فایل در GitHub به مدت هفت روز نگهداری می‌شود؛ ساخت مجدد از سورس همیشه در دسترس است.

## ساخت از سورس

روی ویندوز، SDK دات‌نت ۱۰ را نصب و `setup.cmd` یا `build-windows.cmd` را اجرا کنید. دستور معادل:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/build-original-windows.ps1
```

خروجی: `dist/FreeSMS-Net10/FreeSMS.exe` به همراه پوشه‌های وابسته. ساخت، مستقل از نصب runtime و با ReadyToRun انجام می‌شود. `run.cmd` همین خروجی را باز می‌کند؛ `preview.cmd` پیش‌نمایش فرم اصلی را بدون بانک نشان می‌دهد.

راه‌حل `dotnet/FreeSms.slnx` فقط پروژه‌های فعال .NET 10 را شامل می‌شود. به Visual Studio کامل نیازی نیست.

## بانک اطلاعات

- نمونهٔ اختصاصی LocalDB: `(localdb)\FreeSMS`
- نام بانک: `school_af_kbr`
- محل داده: `%LOCALAPPDATA%\free-sms\windows-db\school_af_kbr`
- اتصال با حساب ویندوز انجام می‌شود.

بانک اولیه فقط یک بار و به صورت اتمیک کپی می‌شود. بانک موجود بازنویسی نمی‌شود. ۴۴ اسکریپت به‌روزرسانی اصلی به صورت تراکنشی اجرا و ثبت می‌شوند. برای استفاده از SQL Server بومی موجود با طرح سازگار، متغیر `FREE_SMS_CONNECTION_STRING` را تنظیم کنید؛ به‌روزرسانی‌ها روی بانک انتخاب‌شده انجام خواهند شد.

## بررسی اجرا

`check-windows.cmd` آزمون‌های بانک، محاسبات گزارش، کنترل‌ها، فرم‌ها و راه‌اندازی ورود را اجرا می‌کند. آزمون بانک فقط نمونهٔ موقت خودش با پیشوند `FreeSmsCheck_` را حذف می‌کند.

در اجرای موفق [آزمون ویندوز](https://github.com/mujtabahassani0101/freesms/actions/runs/41490887246)، هر ۸۹ فرم اصلی روی .NET 10 رندر شدند؛ راه‌اندازی بانک و ورود اصلی موفق بود. ۱۸ بررسی بانک، ۴۰ بررسی محاسبات و خروجی گزارش و ۱۳۴ بررسی کنترل‌ها، رندر ۹۸ قالب گزارش، چاپ ۳۰۰ DPI و بستهٔ مستقل گذشتند. هدف .NET 10 و ReadyToRun هر چهار اسمبلی برنامه نیز بررسی شد. تصاویر نمونه در `validation/previews` و نتایج در `validation` قرار دارند.

رندر فرم و دادهٔ نمونه، برابری همهٔ عملیات با نسخهٔ اصلی را ثابت نمی‌کند. تطبیق دستی همهٔ جریان‌های کاری، صفحه‌بندی گزارش‌ها با دادهٔ واقعی و عملیات Excel هنوز کامل نشده است.
