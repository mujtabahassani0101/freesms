# Recovered native export controllers — static audit

This is a static audit at source5faa270; none of these four original export buttons is certified by it. They still instantiate Excel.ApplicationClass, open a binary template, write returned headers at row1 and DataRow.ToString values from row2, save XLS and quit. They mutate the UI thread culture to en-US without restoring it, perform queries/cell writes synchronously and lack complete failure cleanup. A managed replacement must preserve the recovered data contract and inspect template-only columns and formatting before replacing those templates. Merely writing a generic workbook is insufficient.

## Template inspection

A direct ExcelDataReader inspection of the recovered binary files found Mark.xls Sheet1 has one row/seven columns: ردیف, Code (text format @), codedars, نام, نام خانوادگی, نام درس, mark (0.00). The original query overwrites the first six titles, so the seventh blank mark-entry column is an essential template-only field. Mark2.xls has one row/19 columns, including text-formatted پرونده identity and 0.00 grade/component columns. Std.xls has an empty Sheet1 (zero rows/columns). The asdb0 code references xls/sms.xls, but that file is absent from the current project/package; do not label its current export usable. No replacement has been implemented by this inspection.
