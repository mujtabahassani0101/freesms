# Explicit grid save and SQL rollback verification

The fraction rejection assertion in Windows run41530385450 failed during an explicit DataGridView.EndEdit call. The native WinForms source invokes its internal end-edit path with validation disabled. GridEX therefore now exposes TryEndEdit, sharing the existing numeric validator with CellValidating; explicit attendance saves stop when that guard rejects the raw editor text. Tests require the stored integer to remain unchanged and no data-error dialog. Numeric range checks use the bound DataColumn type, and string columns retain their normalized text.

References: [Microsoft EndEdit API](https://learn.microsoft.com/en-us/dotnet/api/system.windows.forms.datagridview.endedit?view=windowsdesktop-10.0) and [native WinForms implementation](https://github.com/dotnet/dotnet/blob/b0f34d51fccc69fd334253924abd8d6853fad7aa/src/winforms/src/System.Windows.Forms/System/Windows/Forms/Controls/DataGridView/DataGridView.Methods.cs).

CellEndEdit now compares its original and final values before publishing the compatibility CellUpdated event. Ending an unchanged edit or canceling invalid input must not mark a form dirty. Numeric component tests and both attendance reopen/close scenarios verify this behavior. This is a new repair, pending native Windows execution.

Database.Transaction also checks whether its SQL transaction remains valid before rolling back an operation failure. A server-aborted transaction must retain its original SQL error, rather than replacing it with an already-completed rollback error. A failure of an active rollback is aggregated with the original failure. The new SQL XACT_ABORT test verifies both the error and absence of partial writes. Microsoft's [SqlTransaction documentation](https://learn.microsoft.com/en-us/dotnet/api/microsoft.data.sqlclient.sqltransaction?view=sqlclient-dotnet-7.1) describes the connection property and the already-rolled-back exception case.
