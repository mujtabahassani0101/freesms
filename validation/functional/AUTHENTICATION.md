# Original login and password-change regression

Status: the administrator/password-change baseline passed in run41559110225 (sourcecf7dfd7). The non-admin extension below passed in run41560201196 (source4a3a0eb).

The recovered login button and password-change entry button contained special branches accepting a fixed vendor override without checking the selected account's saved password. Those two branches have been removed. Both buttons now use the existing account-password validation, including its original legacy-format migration and permission-loading logic. Stored production passwords, accounts and permissions are not rewritten by this patch.

The authentication worker runs only under the guarded disposable navigation database. It snapshots the fixture administrator's pwd/pw, assigns an owned test password using the existing encoder and format398, and drives the actual login/password buttons. Empty, incorrect and former override values must show the exact rejection and leave the session unauthenticated. An incorrect current password must not open password editing; the correct one must open it. Mismatched new passwords and declining confirmation must preserve the saved password. Confirming a matching replacement must persist the encoded account-specific value; on reopening login, the old password must fail and the new password must authenticate the selected administrator. Finally the fixture password and session fields are restored.

The extended scenario also inserts an owned non-admin account, encoded with its own ID and only section1/grade1. Its real login must load exactly those permissions. The original class form must initialize, while the original student form must reject access with the exact permission warning. Accounts with no section permissions and accounts with no grade permissions must remain unauthenticated after the corresponding original warnings. The temporary user is deleted during cleanup. This extension passed through the actual original login and form handlers in run41560201196.

This baseline does not yet verify the complete non-admin permission matrix, malformed encrypted permission payloads, legacy-format migration, account management, logout, session switching, all password lengths/characters or every keyboard path. Those remain required by PLAN.md. No real user's account is used by this test.

Prepared follow-up (native execution pending): the original account decoder may throw on malformed nested Base64 or invalid substring data. A wrapper now reports invalid stored account information and restores the prior section/grade context when validation fails. It preserves the original validator and accepted legacy formats. The original login and password-edit buttons are exercised with independently corrupted pwd/per/xPaye in the owned account, requiring rejection without partial permission changes. Correcting all three fields must permit login again; deleting the selected account after the login window opens must also reject cleanly. SQL/connection exceptions are not classified as malformed credentials by this wrapper. These follow-up cases passed in run41562748761 (sourced5a5af1), including repaired-account recovery and a deleted selected account. The remaining permission/legacy-format scope is unchanged.
